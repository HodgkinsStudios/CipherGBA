# CipherGBA v0.1 — Local verification record

**Date:** November 15, 2026. **Scope:** source build and regression tests in the available Linux x86_64 environment. These observations apply to the supplied v0.1 source tree, not to Windows/macOS binaries that have not yet been produced from the fresh repository.

## Build and CLI

The X11 frontend and separate shared/static core libraries compiled successfully with CMake, GNU C++17, system X11 and zlib. The release-mode build used `-DCIPHERGBA_FRONTEND=X11 -DCIPHERGBA_NATIVE_TUNING=OFF -DPIXELGBA_ENABLE_LTO=OFF -DCIPHERGBA_BUILD_PERSISTENCE_SMOKE=ON`.

- `bin/CipherGBA --version` reported **CipherGBA v0.1.0**.
- `bin/CipherGBA --help` completed successfully.
- `CipherGBA_PersistenceSmoke` **PASS**: SRAM, Flash64/Flash128, EEPROM512/EEPROM8K, persistent battery/state/TAS/AVI regressions; PPU HBlank clock 1006 and IRQ/frame boundaries.
- `CipherGBA_CpuPhaseSmoke` **PASS**: Thumb `LDRH` bus phase, HBlank polling, Timer0 latch.

## Complete numeric suite — both BIOS modes

A fresh execution of the supplied private test ROM, with separate test runs for each of 13 numerically scored categories, produced:

| Firmware mode | Result | Failures |
| --- | ---: | --- |
| Integrated HLE | **6,994 / 6,998 (99.9428%)** | Four HBlank cases |
| User-supplied original 16 KiB BIOS | **6,994 / 6,998 (99.9428%)** | The same four HBlank cases |

The suite ROM SHA-256 was `8cf68cd31c5468a70aca8a1c5b63dc372fe755c40b446cf6aa6d0fc6e3a1f035`. The original BIOS and the suite are not distributed with CipherGBA. The separate Video category is visual-only and not counted. These four disagreements remain unresolved; see [Accuracy](ACCURACY.md).

## Not demonstrated by this local verification

- Compiling and launching the Windows, macOS and Linux SDL2/AppImage/Flatpak packages generated by GitHub Actions.
- Manual gameplay, sound/controller input, display dialogs and persistence on clean devices.
- Interactive full-game compatibility or full-speed operation across all hosts.
- Apple notarization; the package workflow performs only ad-hoc signing.

The fresh `main` branch CI workflow must finish successfully before the manual GitHub release publication workflow is used. It produces independently named platform packages and a SHA-256 manifest, and the publication job checks that it uses artifacts from exactly the current `main` commit.
